# Fixes — 6 Aug 2026

These fix the exact issues you flagged from testing.

## 1. "No login button after I log out" (client app)

**Root cause:** the login form only existed as step 6 of the registration
wizard (`step === 5` in `App.tsx`). That `step` value lives only in memory —
it resets to `0` the moment you reload the page, log out, or open a new tab.
So the only way to reach the login form was to walk through the entire
5-step registration wizard again, which is impossible once you're already
registered. That's exactly what you were hitting.

**Fix:** the app now has two independent modes — `Register` and `Log In` —
switchable at any time from tabs in the header, next to "Unique Youths".
- The `Log In` tab is always visible and always works, on every screen.
- After you finish registering, the app automatically switches you to the
  Log In tab (with your username pre-filled) instead of relying on a step
  number.
- Which tab you land on is remembered across reloads/logout (`localStorage`),
  so once you've registered once, opening the app again takes you straight
  to Log In.

## 2. "Numbered slots didn't show in Member Slot Grid" (admin app)

**Root cause:** the Member Slot Grid page only renders the numbered grid
when a "circle" document already exists in the database. Nothing in the
code actually created one automatically — despite the README saying a cycle
"opens automatically the moment someone new registers." That claim wasn't
actually implemented, so with 0 circles you'd see an empty page with no
slots and nothing to assign your member into. This is what you saw in your
screenshot (0 active members, no circle tabs).

**Fix, two parts:**
- **Backend:** `complete-registration` now actually opens a circle (with
  `CIRCLE_BASELINE_SIZE` slots, default 20) if none is open yet, the moment
  a member finishes the registration wizard — matching what the README always
  claimed.
- **Admin app:** added a "Start new cycle" / "Start first cycle" button
  directly on the Member Slot Grid page (previously it only existed on the
  Ajo Recipient Draw page), so an admin is never stuck with an empty grid
  and no way to fix it from that screen.

With only 2 test members, remember to set a small cycle size (e.g. `2`) when
starting the cycle so you can actually reach a full, disbursable circle —
same as step 14 of the README's walkthrough already recommended.

## 3. Registration form — password UX

Added directly to the Personal Information step and the Login step:
- **Show/Hide toggle** on every password field (button next to the input,
  no new dependency).
- **Confirm password** field on registration — you can't continue to the
  Bank step unless the password is 8+ characters and the confirmation
  matches.
- **Static password guidance** shown under the password fields: use 8+
  characters, mix upper/lowercase, numbers and a symbol, with an example,
  and don't reuse a password from elsewhere.
- **"Forgot password?"** link on the login form. Since there's no
  self-service reset yet (per the README's Security notes), clicking it
  shows a message telling the member to contact an administrator directly —
  it doesn't pretend to reset anything it can't.
